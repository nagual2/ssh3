# SSH2 vs SSH3 — прогон R3 (S1: WSL loopback, v0.1.15)

Дата: 2026-09-29. Стенд: один хост (loopback, tmpfs `/dev/shm`, диск исключён),
WSL2 kernel 6.18, AMD Ryzen 5 4600H (AES-NI есть). SSH2 = OpenSSH 9.6p1
(`aes128-gcm@openssh.com`, BatchMode); SSH3 = форк nagual2 v0.1.15 (pubkey JWT,
QUIC/HTTP3). Клиент и сервер обоих транспортов — на одном хосте.
Методика: [TESTPLAN.md](TESTPLAN.md) (N≥3–100 прогонов на точку, sha256-верификация,
чередование ABBA, прогревы в корзину). Сырые данные: `bench/results/20260929T065535Z-S1-full/`
и `/tmp/suite/s1_*.csv`.

## Сводка

| Сценарий | SSH2 (OpenSSH) | SSH3 (форк) | Отношение |
|----------|----------------|-------------|-----------|
| B1 push, 512 MiB, k=1 | 365 MB/s | 130 MB/s | SSH2 ×2.8 |
| B2 pull, 512 MiB, k=1 | 488 MB/s | 131 MB/s | SSH2 ×3.7 |
| B3 push агрегат k=2/4/8 | 476 / 531 / 410 MB/s | 197 / 212 / 196 MB/s | SSH2 ×2.4–2.6 |
| B4 handshake (exec `true`) | 280 ms | **126 ms** | **SSH3 ×2.2 быстрее** |
| B5 PTY echo p50 | 0.08 ms | 0.08 ms | паритет |
| B8 tar 1100 файлов | 28.2 MB/s | **58.3 MB/s** | **SSH3 ×2.1 быстрее** |
| B8 per-file (100 файлов) | 0.48 MB/s | **5.33 MB/s** | **SSH3 ×11 быстрее** |
| B9 команда в новый коннект | 282 ms | 133 ms | SSH3 ×2.1 быстрее |
| B9 команда через ControlMaster | **15.7 ms** | — (нет CM) | цель Stage 3.5 |
| B6 CPU сервера под нагрузкой | mean 0.5%, RSS 15 MB | mean 16.1% (пик 251%), RSS 151 MB | цена SSH3 |

## Чтение результатов

1. **Throughput**: на loopback SSH2 (kernel AES-NI) отрывается в ~3 раза — это чистая цена
   userspace-крипто и QUIC-стека в Go. На реальной сети гигабайтного канала (~118 MB/s)
   разрыв упрётся в сеть и станет малозначимым (LAN-замер CTO_TASK: ×1.5).
2. **Мультиплексирование**: агрегат k=8 у SSH3 почти не растёт (196 против 130 MB/s
   одиночного) — коннект насыщается одним ядром; у SSH2 рост тоже останавливается (410–531).
3. **B4/B9**: быстрый handshake — сильная сторона SSH3 (QUIC 1-RTT + один round-trip auth).
4. **B8**: на потокe мелких файлов tar-стримом SSH3 вдвое быстрее; пофайлово — в 11 раз
   (лёгкий QUIC-коннект против spawn+auth scp). Но настоящий ControlMaster (SSH2: 15.7 ms/exec)
   недостижим для SSH3, пока нет мультиплексирования сессий — именно это делает Stage 3.5.
5. **Цена**: серверный процесс SSH3 ест заметно больше CPU (userspace-крипто) и памяти.
   На слабых железках (Atom) ожидаемо хуже — см. оговорку TESTPLAN §9.2.

## Ограничения прогонов

- Loopback: сетевой фактор исключён сознательно; LAN/WAN-прогоны — отдельная серия.
- k>1 сценарии используют уменьшенный блок (256/128/64 MiB) — суммарный след ≤1 GiB
  в /dev/shm (3.8 GiB).
- Один сбойный прогон из 100 в B9 ssh3cli (транзиент) — отбракован верификацией.
